MCP

时间来到19:59。我还想让Ai可以执行Python代码。于是我开始研究MCPMCP（Model Context Protocol，模型上下文协议）MCP 是一个开放协议，由 Anthropic 于 2024 年 11 月推出，旨在标准化 LLM 应用与外部数据源、工具之间的连接方式。可以把它理解为 AI 应用领域的“USB-C 接口”：过去每个 AI 工具都要单独写对接代码，MCP 提供了一套统一的通信规范，让模型能够以标准方式发现、调用外部工具。协议本身基于 JSON-RPC，定义了 Hosts（发起连接的 LLM 应用）、Clients（宿主内的连接器）和 Servers（提供上下文与能力的服务）三种角色。文中作者配置的 RunPY 就是一个 MCP Server，作用是让 AI 能够执行 Python 代码。服务。

  • 00:04–00:06：配置 systemdsystemd / systemd 用户服务systemd 是 Linux 上主流的系统与服务管理器，负责启动、停止、监控服务进程，并支持开机自启。systemd 用户服务（systemctl --user）是在用户级别运行的服务，不需要 root 权限，在用户登录后启动；配合 loginctl enable-linger 也可以让用户服务在开机时即启动、即使用户未登录也保持运行。作者在服务器上配置 AstrBot 开机自启时，遇到的“权限问题”就出在这一层。 用户服务/开机自启时遇到权限问题。
  • 00:11–00:16：处理部署中的网络问题：DNS 解析失败DNS 解析失败DNS 解析是把域名转换成 IP 地址的过程。解析失败的常见原因包括：DNS 服务器不可达或配置错误、防火墙/安全组拦截了 53 端口（DNS 查询端口）、/etc/resolv.conf 中的 nameserver 无效、域名未完成实名或备案等。文中作者在部署后期遇到的 DNS 问题，属于云服务器网络环境下的典型排障场景。、NginxNginx / bind() to …:5000 failedNginx 是一个高性能的 Web 服务器与反向代理。bind() 是服务端程序绑定 IP 和端口以监听请求的系统调用。bind() failed 通常有两种典型原因：端口已被其他进程占用（Address already in use），或者权限不足（如非 root 用户尝试绑定 1024 以下的端口）。文中报错 bind() to 100...*:5000 failed，结合 5000 端口和 Tailscale IP 来看，更可能是该 IP 地址在当前网络接口上不存在或不可绑定（Cannot assign requested address），属于 Tailscale 虚拟 IP 与 Nginx 监听配置不匹配导致的排障问题。 bind() to 100.*.*.*:5000 failed、Tailscale IP 配置等。
