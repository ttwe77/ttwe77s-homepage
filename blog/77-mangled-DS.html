<script id="theme-init">
    (function () {
        try {
            var saved = localStorage.getItem('theme');
            var dark = saved
                ? saved === 'dark'
                : window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)').matches;
            document.documentElement.setAttribute('data-theme', dark ? 'dark' : 'light');
        } catch (e) {
            document.documentElement.setAttribute('data-theme', 'light');
        }
    })();
</script>

<!-- 字体初始化：在样式解析前应用上次选择的字体，避免刷新时字体闪变 -->
<script id="font-init">
    (function () {
        try {
            var DEFAULT_STACK = "'Blog-WenYuan', 'Blog-WenYuan-Fallback', var(--font-fallback)";
            var raw = localStorage.getItem('blog-font');
            // 用户没设置过：默认使用七七柔和圆体
            if (!raw) {
                document.documentElement.style.setProperty('--font-sans', DEFAULT_STACK);
                return;
            }
            var pref = JSON.parse(raw);
            if (pref && typeof pref.stack === 'string' && pref.stack) {
                document.documentElement.style.setProperty('--font-sans', pref.stack);
            }
        } catch (e) { }
    })();
</script>

        <h2 id="0834--侧滑补了事件没补对地方">08:34 · 侧滑：补了事件，没补对地方</h2>

        <blockquote>
        <p><code>修复BUG：手机safari侧滑没有完全滑开（没有滑动到底），侧滑菜单不会完全展开，而是卡在那里不再响应侧滑手势。此时点击按钮仍可展开收起侧滑，但使用侧滑手势不再能展开</code></p>
        </blockquote>

        <p>这个问题上一轮已经修过一版。当时的表现是画面和实际状态对不上：<code>Safari</code>在滑动过程中被拦下页面默认动作后，有时会漏掉“手指抬起”的收尾信号，导致收尾逻辑不执行，手势卡在拖拽中。看起来抽屉已经展开，但内部状态还是关着，遮罩没出来，点空白处没反应；点“收起边栏”时状态本来就是关，也不会触发重画，按钮像没作用。电脑上的浏览器不会漏这个信号，所以桌面上一直测不出来。</p>

        <p>上一版补了四件事：手指抬起或触摸被打断时强制收尾；新一次触摸开始前，先把上一次没收拾干净的手势按当前位置收掉；触摸被系统打断时不再一律弹回，而是按当前位置停住；判断“停住后再松手”改用当前时间，不再信事件自带的时间。另外把状态变化改成每次写入都同步画面，哪怕状态早就是关，点一下也能把抽屉收回去。</p>

        <p>这就是“补事件”的思路：哪个信号没来，就再挂一个能兜住它的信号。</p>

        <p>但我一试，症状变了没消失：拖到一半抽屉冻在中间，之后手势彻底没反应，按钮却还能开合。</p>

        <p>它先说好消息：问题不在"记录太多所以慢"这种玄学，在几个特别勤快的代码——每次滑动都把整棵消息树拉出来重新量一遍身高。</p>

        <p>严格按"无感优化"做，四处改动都不碰交互和视觉：</p>

        <div class="table-wrap"><table><thead><tr><th>文件</th><th>改动</th><th>解决什么</th></tr></thead><tbody><tr><td><code>src/app/viewport.ts</code></td><td>触摸滚动判定改为按下时只测一次可滚动祖先；视口高度变量没变就不写样式</td><td><code>touchmove</code> 不再逐层 <code>getComputedStyle</code> + 读 <code>scrollHeight</code> 强制重排</td></tr><tr><td><code>useCurrentMessage.ts</code></td><td>逐条测矩形 → 二分查找</td><td>布局读取从 500 次降到约 9 次</td></tr><tr><td><code>MessageList.tsx</code></td><td>ResizeObserver 回调合并成每帧一次 rAF</td><td>窗口变化时不再一帧内反复读写 <code>scrollTop</code></td></tr><tr><td><code>historyNodes.ts</code></td><td>160 字预览边扫描边截断</td><td>长会话更新时不再对每条回答全文做正则替换</td></tr></tbody></table></div>

        <p>它还给了一个"更狠"的选项没动：<code>content-visibility: auto</code>，只渲染视口附近的消息。效果好得多，但会动到历史跳转和滚动位置的判定——不是无感优化，等我实测完再说。</p>

        <p>然后它问了我两个问题：手机真机上侧滑卡，还是桌面浏览器模拟触屏？现在滑动和拖窗口还卡吗？</p>

        <p>我回了十个字：</p>

        <blockquote>
        <p><code>手机好了，PC浏览器拖窗口还是卡</code></p>
        </blockquote>

        <h2 id="2359--这一次的停手不算本事">23:59 · 这一次的停手，不算本事</h2>

        <p>手机好了，说明第一刀砍对了。PC 拖窗口是另一回事：那个场景里浏览器每一帧都要重排整棵消息树，500 条消息的 Markdown DOM 节点数量是万级起步。</p>

        <p>00:02，它刚开始查"还有哪些代码在 resize 时火上浇油"。</p>

        <p>我取消了。</p>

        <p><strong>PC 拖窗口到今天还卡着。</strong> 这篇记录里这一行，就当欠条。</p>

        <p>Safari 那次我停得心安理得：没有真机数据，猜着改只会更糟。这次不一样——它明明能修，是我不想在凌晨三点看它一条一条试。</p>

        <h2 id="最后vibe-coding-教我的五件事">最后：vibe coding 教我的五件事</h2>

        <p>我在这 64 小时里学到的，没有一条是关于 React 的。</p>

        <p><strong>一、能把现象描述清楚，比能写代码更稀缺。</strong></p>

        <p><strong>二、验收权比实现权重要。</strong></p>

        <p><strong>三、"我不知道，但我能看出来不对"，是一种完整的能力。</strong></p>

        <p><strong>四、能停手，也是能力。</strong></p>

        <p><strong>五、但停手分两种。</strong></p>

        <p>如果重来一次，我会：<strong>报 bug 时把操作路径一步一步写出来。</strong> 提示词"失忆"那条，我写的是"修改-保存-更多操作-系统提示词，改成功了；开启新对话-更多操作-系统提示词，不见了"。它一眼定位到读的是另一层，不用猜。这不是技巧，是免费的精度。</p>

        <p>折腾的乐趣大概就在这里——不是从零造一个，而是把别人搭好的房子，改到自己住着顺手。<strong>只不过这一次，我全程站在门口说"这儿再挪一点"，没有碰过一次砖。</strong></p>
