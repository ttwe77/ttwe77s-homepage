# 悬浮提示插入规范（AI 直接执行）

## 目标

构建博客前，AI 自己阅读 Markdown，把读者可能不懂的术语解释**直接写进正文**。默认使用内联 HTML 写法，与 `tools/genblog/hover-hint.py` 生成的结构、`tools/genblog/docs/SoftEther-L2TP-IPsec.md` 里已有的人工写法保持一致。不要让用户手动打开 GUI 工具。

标准模板（写成一行）：

```html
<span class="hover-hint">显示文字<span class="hover-hint__tooltip"><span class="hint-title">提示标题</span>提示内容</span></span>
```

多要点解释时，在 `提示内容` 里用 `<br>` 换行，例如：

```html
<span class="hover-hint">peer / conn / secret<span class="hover-hint__tooltip"><span class="hint-title">peer / conn / secret</span>strongSwan 的配置概念：<br>conn（connection）：一条 IPsec 连接的完整定义。<br>peer：对端的身份标识。<br>secret：预共享密钥或证书私钥等凭据。</span></span>
```

`md2page.py` 会原样保护 `span` 标签、把 `<br>` 规范成 `<br>`，正文文字再做转义，因此上面的 HTML 可以直接写进 `.md`，构建后就是气泡提示。`[[文字|标题|说明]]` 简写渲染器也支持，但**默认不要用它**，统一用 HTML，方便和现有文章保持一致。

## 什么时候要插入

优先给这些词加提示：

- 专业术语、缩写、英文专有名词、算法/框架/协议名称（如 Tailscale、ACL、strongSwan、L2TP/IPsec、PPP、NAT、WireGuard）。
- 特定版本、规格、标准、配置项、端口，读者不一定知道背景。
- 文章自身没解释、但理解下文必须知道的概念。

不要插：

- 常用词、上下文已经解释得很清楚的词、一眼就懂的词。
- front matter、标题行、代码块、行内代码、链接文字、图片、表格里的文字。
- 已经带有 `<span class="hover-hint">` 的词（不要重复套娃）。
- 上文已经用`<span class="hover-hint">`解释过的词

同一个术语**只在正文首次出现处**插入一次，后面保持原文。提示要贴着原文写：原词是什么样，就包成什么样，例如原文是 `L2TP/IPsec`，就只包这四个字符组成的部分，外面的“协议”等文字留在 span 外面。

## 插入规则（必须遵守）

1. `显示文字` 必须与原文完全一致，包括大小写、数字和符号；只是用 `<span class="hover-hint">...</span>` 把它包起来。
2. 结构固定为三层：最外层 `hover-hint` 包显示文字，内层 `hover-hint__tooltip` 包标题和内容，`hint-title` 只包标题。不要漏标签、不要嵌套第二条提示。
3. `提示标题` 简短直接，可以是原词，也可以是「原词（英文全称，中文译名）」这种形式，例如 `ACL（Access Control List，访问控制列表）`。
4. `提示内容` 一到几句话讲清「是什么 / 用来干什么 / 在本文里对应哪件事」，不要只把原词换句话重复一遍。多个要点用 `<br>` 分隔，不要用 `<p>`、`<div>`、`<strong>` 等其他标签。
5. 标签内部写纯文本；中文引号、全角括号、ASCII 字符都可以直接用。不要手写 HTML 实体，也不要用 Markdown 的 `**粗体**`、`\`代码\`` 等语法去格式化提示内容。
6. 不要改变原文的 Markdown 结构，只做这一处包裹；不要顺手改写句子、不要改 front matter。
7. **遇到不确定的术语，用搜索工具查权威资料，交叉验证后再写解释。** 不要凭印象编造。
8. 搜不到可靠依据、或存在多种冲突说法时：跳过该词，或在解释里明确写「通常指……，具体含义依上下文而定」，不要把猜测写成事实。
9. 禁止插入在代码“`代码中不能插入悬浮提示`”和代码块中插入悬浮提示。

   ```text
   代码块中不能插入悬浮提示
   ```

## 执行流程

1. 通读输入的 Markdown，列出准备加提示的候选术语。
2. 对拿不准的词用搜索工具核实含义，记下依据。
3. 直接编辑 Markdown 源文件，按上面的 HTML 模板插入提示。若文件不在 `tools/genblog/docs/`，构建脚本会自行复制，仍以用户给的输入文件为准。
4. 照常运行构建脚本，并按 `WORKFLOW.md` 校验产物。
5. **构建完成后，主动告诉用户这次插入了哪些解释**：用列表或表格逐条给出「术语 / 提示标题 / 解释要点 / 是否经过搜索核实」；如果一条都没插，也明确说明「本文没有需要额外解释的术语」。
6. 全程不执行任何 git 写操作。

汇报示例：

```text
本次插入的悬浮提示：
- Tailscale（标题：Tailscale）— 基于 WireGuard 的虚拟组网工具，靠 P2P 或 DERP 中继组网；已搜索核实。
- L2TP/IPsec（标题：L2TP/IPsec）— L2TP 挖隧道、IPsec 负责加密和认证的组合 VPN 技术；已搜索核实。
- WireGuard（标题：WireGuard）— 现代轻量 VPN 协议，代码量小、内核原生支持；已搜索核实。
```

## 人工兜底工具（不需要主动向用户解释）

`tools/genblog/hover-hint.py` 是一个 PyQt5 桌面小工具，供用户手动编辑悬浮提示：拖入 `.md` 文件，填「显示的文字 / 提示标题 / 提示内容」，点「查找 / 替换」逐个替换，支持撤销、保存、另存为。它生成的就是上面的 HTML 结构；`publish_blog.py` 不会启动它，构建脚本也不会自己改写提示内容。只有在用户自己想手动改提示时才需要提到它。
