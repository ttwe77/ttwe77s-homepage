# QQ机器人二周目：从立绘对话框到跨次元陪伴

## 开头

继上次接入机器人的折腾，这次就是纯纯无聊，想要玩玩插件。

我最先是因为看到一个插件“[传话筒·立绘对话框](https://github.com/bvzrays/astrbot_plugin_chuanhuatong)”，它可以拦截<span class="hover-hint">LLM<span class="hover-hint__tooltip"><span class="hint-title">LLM = Large Language Model，大语言模型</span>指用海量文本训练出来的 AI 模型，能理解并生成自然语言，比如文章里的 DeepSeek 就是 LLM。
在文中，LLM 负责：扮演天童凯伊、生成对话、写日记/日程/梦境、决定是否主动发消息、调用搜索或 MCP 工具等。</span></span>的输出然后将输出放进类似GalGame的对话框中，以图片形式发出来。

## 构思提示词

不过要玩这个总得有一个对象吧？所以我最先选择的是<span class="hover-hint">我推<span class="hover-hint__tooltip"><span class="hint-title">我推「推し」（おし / oshi）</span>“我推” 是网络流行语，源自日语 「推し」（おし / oshi），原指在偶像、动漫、游戏等圈子中最喜欢、最支持的那个角色/偶像，类似“本命”“墙头”“主推”。在文章里，“我最先选择的是我推‘天童 凯伊’”，意思就是：天童凯伊是我最喜欢、最想推的角色，所以第一个就想到拿她来做QQ机器人角色扮演。</span></span>“<span class="hover-hint">天童 凯伊<span class="hover-hint__tooltip"><span class="hint-title">天童凯伊（天童 ケイ / Kei）</span>《蔚蓝档案》角色，最初是天童爱丽丝体内的另一个人格，由无名祭司创造的AI，原名“Key”，使命是引导爱丽丝成为“无名诸神的王女”执行方舟计划。她最终选择保护爱丽丝而牺牲，后经莉音与日鞠协助获得独立的人类肉体，正式成为“天童凯伊”。性格傲娇，对爱丽丝极度宠溺，对老师（玩家）口是心非。</span></span>”，因为《蔚蓝档案》中的角色表情差分很丰富。好的问题来了，<span class="hover-hint">prompt<span class="hover-hint__tooltip"><span class="hint-title">Prompt（提示词）</span>Prompt（提示词）：你发给大语言模型的指令/设定文本，用来告诉它“你是谁、怎么说话、在什么场景下回复、要遵守什么规则”。在文章里，prompt 主要指作者写给 AI 的角色扮演系统提示词：设定凯伊的身份背景、外貌、性格、说话风格、QQ私聊/群聊规则、主动消息规则、MCP工具权限等，让模型稳定扮演“天童凯伊”来陪伴老师。</span></span>怎么写？

在我高强度的搜索后，发现有现成的。我先在[opentavern.pages.dev](https://opentavern.pages.dev/)上拿到了凯伊的角色卡，然后又从[uGmTEAM](https://github.com/uGmTEAM)那拿到了基于<span class="hover-hint">AstrBot<span class="hover-hint__tooltip"><span class="hint-title">AstrBot</span>一个开源的一站式Agentic聊天机器人平台及开发框架，支持接入QQ、Telegram、Discord等多种即时通讯平台，具备大模型对话、工具调用、MCP、插件扩展和WebUI管理等功能。本文的所有折腾都基于AstrBot展开。</span></span>的[提示词](https://github.com/uGmTEAM/Blue-Archive-Chinese-Text-AI-prompt/blob/main/Kei.txt)。

> *哇，专业对口啊。这下稳了！*

## 插件配置

OK，Prompt到手，直接来配插件。

### 插件的WebUI

这个插件有一个独立的<span class="hover-hint">WebUI<span class="hover-hint__tooltip"><span class="hint-title">WebUI</span>Web User Interface，即通过浏览器访问的图形化管理界面。AstrBot和传话筒插件都提供了WebUI，用于可视化配置机器人参数、管理插件和上传素材。</span></span>。因为我是部署在我的服务器上的，所以我访问起来可能有点问题，于是我就用<span class="hover-hint">Tailscale<span class="hover-hint__tooltip"><span class="hint-title">Tailscale</span>基于WireGuard的虚拟组网工具，可以在不同设备之间建立安全的点对点网络。作者用 tailscale serve --tcp=18765 命令将服务器上的插件WebUI端口通过Tailscale网络转发出来，以便远程访问。</span></span>的TCP转发：

```bash
# 将 Tailscale 网络内的 18765 端口，转发到本地的 18765 端口
tailscale serve --tcp=18765 http://localhost:18765
```

之后发现这个插件监听的IP是0.0.0.0 。所以我这样做是何意味aaa？

然后就是配置插件了。

### 立绘处理

[背景](https://kivo.wiki/data/organize/6)和[角色立绘](https://kivo.wiki/data/character/518)差分我都是在[基沃托斯古书馆](https://kivo.wiki/)上找的，然后嘛......

然后就出事了，WebUI不知道为什么最大文件上传大小在1M以内。于是我就用[<span class="hover-hint">ImageMagick<span class="hover-hint__tooltip"><span class="hint-title">ImageMagick</span>开源的命令行图像处理套件，支持超过200种格式的读写与转换。文中作者用它将PNG立绘批量转换为WebP格式，以绕过插件WebUI的1MB上传限制。</span></span>](https://imagemagick.org/)（官网居然换了一个style，有点认不出来了）将所有的png素材转成了webp。

> *自己不兼容自己研发的格式那可太搞笑了*

然后呢我就嫌Windows自带的“照片”软件不好用（截图工具打不开Webp）。于是我就去找平替。我最初是让DeepSeek用Python写一个看图软件的，结果软件优化得太差，我懒得维护。那我就去网上找现成的咯。

我找到的看图软件是[<span class="hover-hint">FlyPhotos<span class="hover-hint__tooltip"><span class="hint-title">FlyPhotos</span>一款极速、轻量的开源Windows图片查看器，定位是已停更的Google Picasa Photo Viewer的现代替代品。作者用它来浏览和标记WebP格式的立绘差分，替代Windows自带“照片”应用。</span></span>](https://github.com/riyasy/FlyPhotos)，开源，看图启动的速度挺快的。而且还有缩放模糊（类似无损放大的效果吧）。

> *开源软件让我安心*

找到之后就是开始标记立绘图片的各种情绪了。平时看二创的时候感觉角色那么多表情，表达的情感都是差不多的。结果我越看越不对劲，**这表情的差分怎么有这么多**。我啊，词穷，就让DeepSeek给我生成了一些tag便于我标记。在我弄完之后，满打满算有25个tag。然后问题马上就来了，tag的词性相差不是很大，AI容易弄混。啊那还是用Prompt吧，做都做了不想再改了。
