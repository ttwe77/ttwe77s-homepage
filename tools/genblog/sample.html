CSS 变量：从设计令牌到主题切换

同一个颜色写了十八遍，改一次要全局搜索替换——这是很多人写 CSS 的日常。 这篇文章记录我如何用一个 :root 变量块，把颜色、圆角、阴影和动效曲线收拢到一处， 再顺手实现一键换肤。

CSS 设计系统 主题切换 重构

刚开始写这个博客的时候，我的 CSS 里到处都是硬编码：#21a5e3 出现了几十次， border-radius: 12px 和 14px 混着用，阴影值前后不一致。 直到某天我想把主色调从蓝色换成紫色，改了半小时，还漏掉两处。

那天之后我做了一次彻底的整理，核心只有一个词：设计令牌（Design Token）。

一、为什么需要设计令牌

设计令牌本质上是「把设计决策命名并集中存放」。颜色不叫「蓝色」，而叫 --color-primary；圆角不叫「12 像素」，而叫 --radius-lg。 这样做的收益不止是少打字：

  • 一致性：同一个语义在全站只有一种取值，不会出现「差不多但不一样」的颜色。
  • 可维护：换肤、调间距、改圆角，只需要动一处。
  • 可协作：设计与开发用同一套命名沟通，减少来回确认。
  • 可扩展：新增主题只是新增一组变量，不需要重写组件样式。

变量不是为了少写几个字符，而是为了让「这个颜色是什么」和「这个颜色用在哪」彻底分开。

二、定义第一组变量

所有令牌都挂在 :root 上，它等价于 html 选择器，但优先级更高一点， 也更符合语义。我把它分成四类：颜色、圆角、阴影、字体与动效。

css 
/* 颜色：语义优先，而不是描述外观 */
:root {
  --color-primary: #21a5e3;
  --color-primary-hover: #0E7AE0;
  --color-text-primary: #1F1F1F;
  --color-text-secondary: #737373;
  --color-border: #EDEDED;

  /* 圆角：阶梯式，而不是随手填 */
  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 12px;
  --radius-full: 9999px;

  /* 阴影：把「高度」抽象成层级 */
  --shadow-card: 0 2px 8px rgba(0, 0, 0, .06);
  --shadow-hover: 0 4px 16px rgba(0, 0, 0, .1);

  /* 动效：曲线也值得统一 */
  --ease-out: cubic-bezier(.22, .61, .36, 1);
  --duration: 780ms;
}

注意这里刻意没有写 --color-blue 这种以颜色本身命名的变量。 一旦未来主色改成紫色，--color-blue 这个名字就会变成谎言。

三、命名约定

令牌一多，命名就变成主要矛盾。我的规则很简单：--{类别}-{语义}-{变体}， 类别不超过四个，变体尽量只保留 hover、active、light 三种。

令牌 含义 典型用途
--color-primary 品牌主色 主按钮、链接、强调文字
--color-text-body 正文文字色 段落、列表
--color-border 常规描边 卡片边框、分割线
--radius-lg 大圆角 卡片、弹窗
--shadow-card 卡片默认投影 静止态容器
--ease-out 出场缓动曲线 入场动画、抽屉

关于层级

阴影不要用 --shadow-1、--shadow-2 这种数字。 数字不携带语义，半年后你不会记得 2 和 3 的区别。用 card / hover / popover / modal 更好—— 它直接告诉你这个阴影该用在哪里。

四、深色模式：一次切换，全站生效

变量集中之后，换肤就变成了纯粹的重定义。最省事的做法是先跟随系统， 再用 data-theme 支持手动覆盖。

css 
/* 1. 跟随系统 */
@media (prefers-color-scheme: dark) {
  :root {
    --color-bg-light: #16181D;
    --color-text-primary: #F2F4F7;
    --color-text-body: #C8CDD6;
    --color-border: #2A2E36;
  }
}

/* 2. 手动覆盖：写在 html 上的 data-theme 优先级更高 */
:root[data-theme="dark"] {
  --color-bg-light: #16181D;
  --color-text-primary: #F2F4F7;
  --color-text-body: #C8CDD6;
  --color-border: #2A2E36;
}

JS 那一侧只需要两行：

javascript 
// 切换主题，CSS 变量会自动重算
document.documentElement.dataset.theme = 'dark';

// 记住用户选择
localStorage.setItem('theme', 'dark');
小坑提示：主题切换的瞬间会出现一帧白闪。 解决办法是在 <head> 里内联一段同步脚本， 在 CSS 解析前就把 data-theme 写上去。

五、几个容易踩的坑

  1. 变量不参与级联计算值。浏览器在解析时不会展开变量， 所以不能给 background 里的渐变直接写变量颜色——要写成 linear-gradient(var(--a), var(--b)) 才行。
  2. 回退值要写上。var(--x, #21a5e3) 的第二个参数是兜底， 在用户禁用了变量或主题文件加载失败时能救一命。
  3. 别把变量写进内联样式的性能热路径。频繁用 style.setProperty() 修改会导致样式重算，动画尽量交给 transform 和 opacity。
  4. 不要在媒体查询里重复定义全部变量。只覆盖差异项， 继承下来的部分会自动生效。
  5. 颜色不要只存 HEX。需要透明度时用 rgba() 或 color-mix() 更灵活，否则只能再定义一堆 --color-primary-alpha-10。

六、写在最后

这套东西我用了大概半年，最大的感受是：写 CSS 从「调样式」变成了「定规则」。 以前改一个颜色要担心漏掉哪里，现在只需要改一行，然后刷新看看有没有哪里变得奇怪。

如果你的项目还处在「颜色随手写」的阶段，不用一次性重构完。 先从最痛的那个颜色开始，把它抽成变量，跑一遍看看。习惯一旦建立，剩下的就顺理成章了。

文中提到的 设计令牌 Design Token 设计令牌是把设计决策（颜色、间距、圆角、字体等）抽象成带名字的变量，让设计与开发共用同一套语义。它不是 CSS 独有的概念，Figma、Sketch 等设计工具同样支持。 并不是什么新概念，只是在 CSS 自定义属性普及之后，前端终于可以用原生方式落地它了。
